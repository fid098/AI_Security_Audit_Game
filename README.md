# Security Detection Game

[![CI](https://github.com/fid098/AI_Security_Audit_Game/actions/workflows/ci.yml/badge.svg)](https://github.com/fid098/AI_Security_Audit_Game/actions/workflows/ci.yml)

An Among-Us-inspired security training game. Players inspect short code snippets,
label them as SAFE or VULNERABLE, and receive a post-game audit powered by
Hacktron and Claude. Optional voice summaries are generated via ElevenLabs.

**Winner, ICHack 2026 — Best use of Hacktron CLI and the Claude API.**

## Quick Start (Docker)

The whole stack in one command, with no Python or Node install needed. The stack
starts without any API keys, but rounds are generated by Claude, so playing a
round needs `ANTHROPIC_API_KEY` (see [Running without API keys](#running-without-api-keys)).

```bash
docker compose up --build
```

- Game: http://localhost:8080
- API: http://localhost:8000
- Interactive API docs: http://localhost:8000/docs

## Features
- LLM-generated tasks with realistic vulnerabilities (XSS, SQLi, SSRF, RCE, etc.)
- The number of vulnerable snippets is sampled per round, so it cannot be deduced
- Tutorial mode with Claude-generated per-snippet hints, revealed on demand
  (withheld on HARD)
- Per-task timer, scoring, and ship-system status
- Live Hacktron CLI scan of every missed snippet, run on the server during the
  audit (missed tasks only, for fast, focused audits)
- Claude "Security Mentor" post-mortem summary, informed by the scanner output
- Optional ElevenLabs voice summary, generated on demand from the report
- Audit screen with a scan log and progress ring while the audit runs (the
  on-screen log is an animation; the real scanner output goes to the summary)
- Accuracy by vulnerability type in the report
- Endless mode: 5 easy → 5 medium → hard batches until the first mistake

## Tech Stack
- Frontend: React + Vite + TypeScript
- Backend: FastAPI (Python)
- LLM: Anthropic Claude, via the official `anthropic` SDK
- Scanner: Hacktron CLI (WSL supported)
- TTS: ElevenLabs

## Running Without API Keys

Every external provider is optional, and each degrades independently rather than
breaking the app:

| Missing | Effect |
| --- | --- |
| `HACKTRON_CMD` | Snippets are not statically scanned; the audit notes it and the game plays normally. |
| `ANTHROPIC_API_KEY` | `/generate` and `POST /session` return 503, so no round can start; the client shows the error on the difficulty screen. The mentor summary falls back to a locally generated one. |
| `ELEVENLABS_API_KEY` | `/tts` returns 503; the voice button in the report shows the error. |

So `docker compose up` starts on a clean machine with no configuration, but a
round cannot be played without an Anthropic key.

## Environment Variables

Create a `.env` in the repo root. All values are optional. Variables already set
in the environment (for example by Docker Compose or CI) take precedence over `.env`.

```ini
ANTHROPIC_API_KEY=your_key
ANTHROPIC_MODEL=claude-sonnet-5

ELEVENLABS_API_KEY=your_key
ELEVENLABS_VOICE_ID=your_voice_id   # replaces the built-in voice
ELEVENLABS_MODEL_ID=                # defaults to eleven_monolingual_v1

CORS_ORIGINS=http://localhost:5173,http://localhost:8080

# Hacktron CLI. Use HACKTRON_CMD=wsl on Windows and give the Linux-side path;
# {file} is replaced with the snippet path. Leave unset to skip scanning.
HACKTRON_CMD=wsl
HACKTRON_ARGS=$HOME/.local/bin/hacktron --format json {file}
HACKTRON_MAX_WORKERS=4      # max concurrent scans across the whole server
HACKTRON_TIMEOUT=30         # seconds per scan
```

### Frontend `.env` (client/.env)
```
VITE_API_URL=http://localhost:8000
```

Vite inlines `VITE_*` at build time, so Docker takes it as a build arg instead.

## Scan Concurrency

An audit scans every missed snippet, and each scan is an independent subprocess
that spends nearly all its time blocked. Scans therefore run on a thread pool,
with results returned in request order and a failing scan isolated to its own
snippet rather than aborting the batch.

`HACKTRON_MAX_WORKERS` is a server-wide limit, not a per-audit one: every scan
takes a slot from one shared semaphore before starting its subprocess, so
overlapping audits queue rather than each launching their own scanners. Time
spent waiting for a slot does not count against `HACKTRON_TIMEOUT`.

`server/benchmarks/bench_scan.py` measures the effect. It stubs the scanner with
a fixed latency by default so the result is reproducible without the CLI
installed, isolating scheduling from scanner speed:

```
cd server
python benchmarks/bench_scan.py --snippets 10
```

At a simulated 0.8s per scan with 4 workers:

| Snippets | Sequential | Concurrent | Speedup |
| --- | --- | --- | --- |
| 5 | 4.02s | 1.61s | 2.50x |
| 10 | 8.04s | 2.42s | 3.32x |

Pass `--real` to benchmark against an actual configured Hacktron CLI.

## How It Works
1) Frontend calls `/generate` to get tasks from Claude.
2) Player marks snippets SAFE/VULNERABLE; the browser scores each answer.
3) Frontend calls `/audit` with the missed tasks.
4) Backend runs the Hacktron CLI live on each of those snippets, in parallel.
5) Findings are built from each snippet's labelled vulnerability type; Claude
   writes the mentor summary from those and the scanner output.
6) The report shows accuracy by vulnerability type; ElevenLabs reads the summary
   aloud on request.
7) Endless mode moves to the next difficulty after a perfect batch.

The browser-driven game above scores on the client, so `/generate` returns each
snippet's answer. The `/session` endpoints below are a server-authoritative
alternative that keeps answers on the server; the client does not use them yet.

## API Endpoints (Backend)

Full interactive documentation is generated from the Pydantic schemas at
http://localhost:8000/docs.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/` | Service index, pointing to the docs and health check |
| GET | `/health` | Liveness check |
| GET | `/health/elevenlabs` | Verifies the configured TTS credentials |
| POST | `/generate` | Generate snippets for a difficulty |
| POST | `/audit` | Scan snippets and summarise findings |
| POST | `/tts` | Render a summary to speech |
| POST | `/session` | Create a scored session |
| GET | `/session/{id}/tasks` | Fetch snippets without the answers |
| POST | `/session/{id}/submit` | Submit answers and get a score |
| POST | `/session/{id}/finish` | Finalise and build the audit report |
| GET | `/session/{id}/results` | Fetch the report, computing it if needed |

The session API serves snippets through a separate schema that omits
`isVulnerable` and `vulnerabilityType`, so its answers stay on the server.
Sessions are kept in process memory: they expire after an hour idle (at most
1,000 are held), answers are rejected with 409 once a session is finished, and
concurrent `finish` calls share a single audit. Being in memory, sessions do not
survive a restart or span several server workers.

`/audit` accepts at most 10 tasks of up to 4,000 characters each, with task ids
limited to letters, digits, `_` and `-`.

## Troubleshooting
**/generate returns 503**
- Check Anthropic model name and API key.
- Ensure `.env` is loaded and uvicorn restarted. A variable already set in your
  shell overrides `.env`.

**/generate returns 502**
- Claude replied, but the reply was unusable (wrong number of tasks or invalid
  JSON). Retry; the request itself was fine.

**Hints are missing**
- On HARD, Claude's hints are withheld by design; the UI shows static language tips.
- Otherwise Claude may not be returning `hints`; the UI falls back to the same tips.

**/tts returns 503**
- Check ElevenLabs API key.
- Verify `.env` is loaded (restart uvicorn).

**Hacktron errors on Windows**
- Use `HACKTRON_CMD=wsl` and give `HACKTRON_ARGS` the Linux-side binary path.
  Windows temp paths are converted with `wslpath` automatically.
- Test the CLI directly first:
  ```
  wsl $HOME/.local/bin/hacktron --help
  ```
- Leave `HACKTRON_CMD` unset to skip scanning entirely; the game still works.

**Audits feel slow**
- Raise `HACKTRON_MAX_WORKERS` (default 4) to scan more snippets concurrently,
  or lower `HACKTRON_TIMEOUT` (default 30s) to fail slow scans faster. Because
  the limit is shared, raise it if many players audit at once.
